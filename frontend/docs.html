Introduction

AuthGuard provides a simple, secure REST API for authentication. All endpoints return structured JSON responses.

Base URL

http://localhost:5000/api/auth

Replace http://localhost:5000 with your production backend URL.

Content Type

All requests must include Content-Type: application/json. All responses are in JSON format.

Example Request Headers 
Content-Type: application/json
Authorization: Bearer

Authentication

Most endpoints require authentication via an access token in the Authorization header.

Access Token

Received after successful login or registration. Valid for 15 minutes.

Refresh Token

Stored in an HttpOnly cookie. Automatically rotates on each refresh request.

Token Refresh Flow 
// When access token expires (HTTP 401)
// Automatically call refresh endpoint
POST /api/auth/refresh
// Cookie: refresh_token=... (sent automatically)

{
    "success": true,
    "accessToken": "new_access_token...",
    "refreshToken": "new_refresh_token..."
}

Security Architecture

AuthGuard implements multiple layers of security to protect user accounts and data.

Password Security

FeatureDetail
Hash Algorithmbcrypt with 12 salt rounds (2^12 = 4096 iterations)
Hash Length60 characters (format: $2b$12$...)
Comparisonbcrypt.checkpw() — constant-time comparison prevents timing attacks
StorageOnly the hash is stored; plaintext password is never persisted
NullableUsers who register via Google OAuth have no password_hash

Cookie Security

AttributeValuePurpose
HttpOnlytruePrevents XSS — JavaScript cannot read the cookie
Securetrue (HTTPS)Only sent over encrypted connections
SameSiteStrictPrevents CSRF attacks
Max-Age604800 (7 days)Automatically expires

Account Enumeration Protection

To prevent attackers from guessing valid usernames or emails, the login endpoint always returns the same error regardless of whether the account exists:

Always returns
{
    "success": false,
    "code": "INVALID_CREDENTIALS",
    "message": "Invalid username/email or password."
}

Audit Logging

All authentication events are logged, including both SUCCESS and FAILED attempts. Sensitive information is sanitized before storage:

  • password — removed from details
  • token — removed from details
  • idToken (Google credential) — removed from details

Token Rotation & Replay Attack Protection

Each time a refresh token is used, the old token is revoked and a new one is issued. If an old (revoked) token is replayed, all sessions for that user are immediately revoked, preventing attackers from maintaining access.

Replay Attack Detection Flow
1. User logs in → receives AT1, RT1
2. User refreshes token → RT1 revoked, AT2 + RT2 issued
3. Attacker replays RT1 → Backend detects revoked token
4. ALL sessions for this user are revoked
5. Attacker's RT2 also becomes invalid
6. User must log in again (sacrifice for security)

Token System Deep Dive

Access Token (JWT)

PropertyValue
AlgorithmHS256 (HMAC-SHA256)
Expiry15 minutes (configurable via JWT_ACCESS_EXPIRES_IN_MINUTES)
PayloaduserId, username, email, exp (no sensitive data)
JWT Payload Structure
{
    "userId": "uuid-1234",
    "username": "john_doe",
    "email": "john@gmail.com",
    "exp": 1700000000   // Unix timestamp, 15 min from creation
}

Refresh Token (Session Token)

Unlike the access token, the refresh token is not a JWT. It is a cryptographically random string (80 hex characters) that is stored in the database and linked to a specific session.

PropertyValue
Generationsecrets.token_hex(40) — 80 hex chars
Storagesessions table (database) + HttpOnly Cookie
Expiry7 days (configurable via JWT_REFRESH_EXPIRES_IN_DAYS)
TransmissionHttpOnly Cookie (preferred) or POST body

Integration Guide

AuthGuard is an independent Authentication Platform. Your backend (Flask, Node.js, Django, React, etc.) only needs to verify the JWT Access Token issued by AuthGuard.

Integration Options

MethodDescription
Shared JWT SecretCopy JWT_ACCESS_SECRET to your backend and verify tokens locally
Verify APICall POST /api/auth/verify to validate tokens remotely

Flask Integration

Flask Middleware
import jwt
from functools import wraps
from flask import request, jsonify, g

JWT_ACCESS_SECRET = "access-token-secret-key-12345"  # Copy from AuthGuard

def require_auth(f):
    @wraps(f)
    def decorated(*args, **kwargs):
        auth_header = request.headers.get("Authorization")
        if not auth_header or not auth_header.startswith("Bearer "):
            return jsonify({"error": "Unauthorized"}), 401

        token = auth_header.split(" ")[1]
        try:
            payload = jwt.decode(token, JWT_ACCESS_SECRET, algorithms=["HS256"])
            g.current_user = payload  # { userId, username, email }
        except jwt.ExpiredSignatureError:
            return jsonify({"error": "Token expired"}), 401
        except jwt.InvalidTokenError:
            return jsonify({"error": "Invalid token"}), 401

        return f(*args, **kwargs)
    return decorated

Node.js (Express) Integration

Express Middleware
const jwt = require('jsonwebtoken');
const JWT_ACCESS_SECRET = 'access-token-secret-key-12345';

function requireAuth(req, res, next) {
    const authHeader = req.headers.authorization;
    if (!authHeader || !authHeader.startsWith('Bearer ')) {
        return res.status(401).json({ error: 'Unauthorized' });
    }

    const token = authHeader.split(' ')[1];
    try {
        const payload = jwt.verify(token, JWT_ACCESS_SECRET);
        req.user = payload; // { userId, username, email }
        next();
    } catch (err) {
        if (err.name === 'TokenExpiredError') {
            return res.status(401).json({ error: 'Token expired' });
        }
        return res.status(401).json({ error: 'Invalid token' });
    }
}

app.get('/api/protected', requireAuth, (req, res) => {
    res.json({ message: 'Access granted', userId: req.user.userId });
});

Django Integration

Django Decorator
import jwt
from django.http import JsonResponse
from functools import wraps

JWT_ACCESS_SECRET = 'access-token-secret-key-12345'

def jwt_required(view_func):
    @wraps(view_func)
    def _wrapped_view(request, *args, **kwargs):
        auth_header = request.headers.get('Authorization', '')
        if not auth_header.startswith('Bearer '):
            return JsonResponse({'error': 'Unauthorized'}, status=401)

        token = auth_header.split(' ')[1]
        try:
            payload = jwt.decode(token, JWT_ACCESS_SECRET, algorithms=['HS256'])
            request.user_id = payload['userId']
        except jwt.ExpiredSignatureError:
            return JsonResponse({'error': 'Token expired'}, status=401)
        except jwt.InvalidTokenError:
            return JsonResponse({'error': 'Invalid token'}, status=401)

        return view_func(request, *args, **kwargs)
    return _wrapped_view

React (Frontend) Integration

React API Client
const API_BASE_URL = 'http://localhost:5000'; // AuthGuard URL

class AuthGuardClient {
    constructor() {
        this.accessToken = null;
    }

    async login(usernameOrEmail, password) {
        const res = await fetch(`${API_BASE_URL}/api/auth/login`, {
            method: 'POST',
            headers: { 'Content-Type': 'application/json' },
            credentials: 'include',
            body: JSON.stringify({ usernameOrEmail, password })
        });
        const data = await res.json();
        if (data.success) {
            this.accessToken = data.accessToken;
            localStorage.setItem('authguard_token', data.accessToken);
        }
        return data;
    }

    async callResourceServer(url, options = {}) {
        const headers = {
            'Content-Type': 'application/json',
            'Authorization': `Bearer ${this.accessToken}`,
            ...options.headers
        };
        const res = await fetch(url, { ...options, headers });
        if (res.status === 401) {
            const refreshed = await this.refreshToken();
            if (refreshed) {
                headers['Authorization'] = `Bearer ${this.accessToken}`;
                const retryRes = await fetch(url, { ...options, headers });
                return retryRes.json();
            }
        }
        return res.json();
    }

    async refreshToken() {
        const res = await fetch(`${API_BASE_URL}/api/auth/refresh`, {
            method: 'POST',
            credentials: 'include'
        });
        const data = await res.json();
        if (data.success) {
            this.accessToken = data.accessToken;
            localStorage.setItem('authguard_token', data.accessToken);
            return true;
        }
        return false;
    }
}

Next.js (API Routes) Integration

Next.js API Route
// pages/api/protected.js
import jwt from 'jsonwebtoken';

const JWT_ACCESS_SECRET = 'access-token-secret-key-12345';

export default function handler(req, res) {
    const authHeader = req.headers.authorization;
    if (!authHeader || !authHeader.startsWith('Bearer ')) {
        return res.status(401).json({ error: 'Unauthorized' });
    }

    try {
        const payload = jwt.verify(authHeader.split(' ')[1], JWT_ACCESS_SECRET);
        res.status(200).json({
            message: 'Protected data',
            user: payload
        });
    } catch (err) {
        res.status(401).json({ error: 'Invalid or expired token' });
    }
}

Using the Verify API (No Shared Secret)

If you prefer not to share the JWT secret, your resource server can call the AuthGuard Verify API to validate tokens remotely:

Python Example
import requests

def verify_token(access_token):
    response = requests.post(
        'http://authguard-server:5000/api/auth/verify',
        headers={'Authorization': f'Bearer {access_token}'}
    )
    if response.status_code == 200:
        data = response.json()
        return data['user']  # { id, username, email, ... }
    return None
